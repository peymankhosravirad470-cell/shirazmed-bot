# 🏥 شیراز مدیکال — ربات گردشگری سلامت (بله / تلگرام)

پلتفرم جامع گردشگری سلامت شیراز: رزرو نوبت پزشک از بین **۱۱۴ پزشک واقعی در ۳ تخصص فعال** (cardio، dental، derma — از ۵۰ تخصص پیکربندی‌شده که فقط تخصص‌های دارای پزشک نمایش داده می‌شوند)، پرداخت آنلاین زرین‌پال با تأیید خودکار، رسید PDF فارسی، همراه بیمار، نظرسنجی، اطلاعات بیمارستان‌ها/هتل‌ها/بیمه‌ها/پایانه‌ها و بخش گردشگری — با پشتیبانی سه‌زبانه (فارسی/انگلیسی/عربی).

## 🏗️ معماری

~~~
main.py                    → نقطه‌ی ورود (polling + بوت‌استرپ داده + سرور health)
config.py                  → تنظیمات از env (بدون هاردکد توکن؛ DATA_DIR واحد)
app/
  bot.py                   → ساخت اپلیکیشن + post_init (پل runtime)
  runtime.py               → پل event loop بین سرور health و ربات
  data_seed.py             → 🆕 بوت‌استرپ فایل‌های غایب استاتیک روی دیسک پایدار
  health.py                → سرور HTTP لیارا: health-check + callback زرین‌پال
  handlers/
    start.py               → /start، انتخاب زبان، منوی اصلی
    booking.py             → رزرو واقعی: تخصص ← پزشک ← تاریخ شمسی ← ساعت ← پرداخت
    callbacks.py           → دکمه‌های منو + مرور پزشکان + نمایش داده‌ها + مسیریاب سه‌اپ
    companion.py           → ثبت همراه بیمار
    survey.py              → نظرسنجی رضایت
    meds.py                → یادآور دارو با JobQueue روزانه
    doctor_reg.py          → 🩺 ثبت‌نام مخفی پزشک (رمز از env + تایید ادمین)
  services/
    doctor_loader.py       → لود تخصص‌های دارای پزشک از data/doctors (کش mtime)
    booking.py             → اسلات‌ها (per-doctor) + fail-closed + ذخیره‌ی اتمیک
    payment.py             → زرین‌پال request/verify با قفل هم‌زمانی
    receipt.py             → رسید متن + PDF فارسی (arabic_reshaper + bidi)
app/locales/               → fa / en / ar
data/                      → دیسک پایدار لیارا (نوبت‌ها/تراکنش‌ها/داروها/persistence)
tests/                     → 🆕 ۱۱ سوت آزمون اجباری (python tests/run_all.py)
~~~

## 🚀 راه‌اندازی محلی

~~~bash
pip install -r requirements.txt
export BALE_BOT_TOKEN="توکن-ربات-بله"        # یا TELEGRAM_BOT_TOKEN (یا PLATFORM=telegram)

~~~

## 🧪 آزمون‌ها

~~~bash
python tests/run_all.py        # ۱۱ سوت، ۲۵۰+ ادعا — بدون توکن واقعی و بدون شبکه
~~~

پوشش: نحو/import، JSON و داده‌ی پزشکان، جریان رزرو و fail-closed، چرخه‌ی کامل پرداخت (موفق/ناموفق/لغو/تکراری/مبلغ نامنطبق/شبکه/ذخیره‌ی شکست‌خورده)، رسید PDF، ثبت‌نام پزشک، همه‌ی callbackها و مسیریاب سه‌اپ، یادآور دارو، ریست /start وسط گفتگو، سرور health و استقرار، امنیت لاگ و سه‌زبانه.
GitHub Actions این آزمون‌ها را **قبل از دیپلوی** اجرا می‌کند (`needs: test` در liara.yml).

## 💳 جریان پرداخت (تأیید کامل خودکار)

1. کاربر نوبت را رزرو می‌کند → نوبت `pending` (۱۵ دقیقه اعتبار) + تراکنش `pending` روی دیسک
2. لینک زرین‌پال ساخته می‌شود با `callback_url = {PUBLIC_BASE_URL}/payment/callback?user_id=X`
   — اگر ذخیره‌ی تراکنش شکست بخورد، **لینک صادر نمی‌شود** (قابلیت verify تضمین می‌شود)
3. کاربر پرداخت می‌کند → زرین‌پال کاربر را به همان آدرس برمی‌گرداند
4. سرور `health.py`:
   - `Status=OK` → **verify نزد زرین‌پال با مبلغ ثبت‌شده** → نوبت `paid` → پیام موفقیت + رسید متن + PDF به کاربر
   - اگر verify موفق ولی قطعی‌سازی نوبت شکست بخورد → پیام صادقانه «نیازمند پیگیری» + هشدار به ادمین
   - `Status=NOK` → آزادسازی اسلات + پیام «پرداخت ناموفق»
   - callback تکراری → صفحه‌ی «قبلاً تأیید شده» بدون پیام/رسید دوباره
5. صفحه‌ی HTML سه‌زبانه (به زبان کاربر، راست‌به‌چپ) نتیجه را نشان می‌دهد

> ⚠️ مهم: متغیر `PUBLIC_BASE_URL` باید دامنه‌ی عمومی اپ روی لیارا باشد تا callback کار کند. دامنه‌ی پیش‌فرض `https://shirazmedical.iran.liara.run` است.

## 🩺 دیپلوی روی لیارا

- `liara.json`: اپ `shirazmedical` + دیسک `data` روی `/app/data`
- با هر push به `main`: اول **آزمون‌ها** اجرا می‌شوند، بعد دیپلوی (`.github/workflows/liara.yml` با `needs: test`)
- هر روز ساعت ۶:۳۰ صبح تهران، `collect.py` داده‌ی پزشکان را آپدیت می‌کند (`.github/workflows/collect.yml`)
- 🆕 بوت‌استرپ داده: Dockerfile یک کپی از `data` را در `/app/data_seed` نگه می‌دارد؛ در startup فقط فایل‌های «غایب» روی دیسک پایدار از آن ساخته می‌شوند (هیچ‌وقت بازنویسی نمی‌کند) تا با دیسک خالی/نو هم منوها خالی نمانند
- متغیرهای حساس (توکن‌ها/رمزها) فقط در تنظیمات لیارا (env) — هیچ رمزی در کد، لاگ یا GitHub Actions هاردکد نیست
